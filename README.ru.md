# WebTelemt by V2P

[English](README.md) | **Русский**

## Что это

WebTelemt — установщик собственного **WEB-прокси для Telegram** на Ubuntu 24.04 одной командой.

WEB-прокси — новый тип прокси в Telegram. Трафик Telegram идёт внутри обычных HTTPS-запросов к вашему домену на порт 443. Для провайдера или системы фильтрации сервер выглядит как обычный сайт с действительным сертификатом. Если открыть домен в браузере, будет нейтральная страница «скоро открытие».

## Что делает

- За несколько минут превращает чистый VPS на Ubuntu 24.04 в рабочий WEB-прокси для Telegram.
- Получает и сам продлевает бесплатный сертификат Let's Encrypt для вашего домена.
- Показывает сайт-заглушку всем, у кого нет ключа. Страницу выбираете из трёх.
- Выдаёт готовые ссылки (`tg://` и `https://t.me/…`) и QR-код для Telegram.
- Ставит команду `webproxy` для управления: состояние, ссылки, смена заглушки, новый секрет, журналы, обновление, удаление.

```
Telegram ──► скрытый WebView ──HTTPS :443──► Caddy ──HTTP──► Telemt ──► дата-центр Telegram
(MTProto)    (страница-мост)                 (TLS, настоящий   127.0.0.1:18080
                                              сертификат)
```

Ничего не подделывается: домен указывает на сервер, сертификат настоящий, отвечает настоящий веб-сервер. Собственное шифрование Telegram (MTProto) работает от клиента до серверов Telegram, HTTPS — дополнительный слой сверху.

## Что устанавливается автоматически

| Компонент | Зачем |
|---|---|
| Обновления системы | `apt update && apt upgrade` перед всем остальным |
| [Caddy](https://caddyserver.com/) (официальный apt-репозиторий) | HTTPS на 443 и автоматический сертификат Let's Encrypt |
| [Telemt](https://github.com/telemt/telemt) 3.5.14 | Сам прокси в WEB-режиме. Скачивается из релизов GitHub, контрольная сумма SHA-256 сверяется |
| Сервис systemd `telemt` | Запуск прокси при загрузке, работает от непривилегированного пользователя `telemt` |
| Страница-заглушка | Статический сайт для всех, у кого нет ключа |
| Команда `webproxy` | Управление после установки |
| Утилиты | `curl`, `jq`, `qrencode`, `dnsutils`, `openssl` и другие мелкие зависимости |
| Правила ufw | Открываются порты 80 и 443, **только если ufw уже включён** |

Настройки SSH установщик не трогает, выключенный файрвол не включает.

## Подготовка сервера

Перед запуском установщика нужно:

1. **VPS на Ubuntu 24.04** (x86_64 или arm64) с доступом root. Хватит 1 vCPU и 1 ГБ RAM.
2. **Постоянный публичный IPv4-адрес.**
3. **Домен или поддомен, привязанный к серверу:**
   - создайте **A-запись** `ваш.домен → IP сервера`;
   - на Cloudflare включите режим **DNS only** (серое облако), без проксирования;
   - **AAAA-записи быть не должно**, если только она не указывает на этот же сервер. Иначе Let's Encrypt не выдаст сертификат;
   - проверьте, что запись работает: `dig +short A ваш.домен @1.1.1.1` должен вернуть IP сервера.

   Берите нейтральное имя (`app`, `cdn`, `static`…), а не `tg` или `proxy`.
4. **Порты 80 и 443 свободны и открыты.** Их не должен занимать никто другой, а файрвол хостинга должен их пропускать. Порт 80 нужен для получения сертификата. **Порт 443 обязателен:** Telegram подключается к WEB-прокси только по 443, на других портах работать не будет.
5. **Исходящий доступ в интернет** к GitHub, Let's Encrypt, репозиторию Caddy и Telegram.
6. **Клиент Telegram с поддержкой прокси типа WEB** (свежие Telegram Desktop, Android, iOS).

## Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/V2P-Dev/WebTelemt-by-V2P/main/webproxy-install.sh -o webproxy-install.sh && sudo bash webproxy-install.sh
```

## Как проходит установка

Установщик спрашивает только три вещи: **домен**, **страницу-заглушку** (1–3) и, по желанию, **e-mail** для Let's Encrypt. Дальше всё идёт без вопросов, в 10 шагов:

1. Обновление системы (`apt update && apt upgrade`).
2. Зависимости и команда `webproxy`.
3. Определение публичного IP и проверка DNS: домен должен указывать на этот сервер.
4. Проверка портов: 80 и 443 должны быть свободны.
5. Caddy из официального репозитория.
6. Загрузка Telemt и проверка контрольной суммы.
7. Конфиг Telemt с новым секретом и страница-заглушка.
8. Запуск сервисов; правила ufw, если он включён.
9. Проверка: прокси слушает, HTTPS работает, сертификат действителен.
10. Готовые ссылки и QR-код на экране, копия в `/root/webproxy-links.txt`.

Повторный запуск безопасен: секрет сохраняется, ссылки продолжают работать.

### Установка без вопросов

```bash
sudo bash webproxy-install.sh --domain ваш.домен --decoy 1 --email you@example.com -y
```

| Опция | Описание |
|---|---|
| `--domain D` | Домен прокси |
| `--decoy N` | Страница-заглушка, 1–3 |
| `--email E` | E-mail для Let's Encrypt (необязательно) |
| `--telemt-version V` | Версия Telemt (по умолчанию закреплённая, либо `latest`) |
| `--new-secret` | Новый секрет, даже если конфиг уже есть |
| `--skip-dns-check` | Не проверять DNS |
| `-y`, `--yes` | Без вопросов; ошибка, если не хватает значений |
| `--force` | Не проверять версию ОС |

## Управление

```
webproxy status                    сервисы, сертификат, активные сессии
webproxy links [--qr]              ссылки (и QR-код)
webproxy decoy [N]                 список заглушек / сменить на N
webproxy rotate-secret             новый секрет (старые ссылки перестанут работать)
webproxy restart                   перезапустить Telemt и Caddy
webproxy logs [telemt|caddy] [-f]  журнал, секреты скрыты
webproxy update [VERSION]          обновить Telemt (по умолчанию latest)
webproxy uninstall                 полное удаление
```

## Ограничения

- **Голосовые и видеозвонки могут не работать** через WEB-прокси Telemt.
- Тип прокси WEB новый, часть версий Telegram может его не поддерживать.
- Если заблокируют домен или IP, маскировка не поможет: нужен новый домен или сервер.
- **Держите ссылку в секрете.** Пользоваться прокси может любой, у кого она есть. Если ссылка утекла, выполните `webproxy rotate-secret`.
